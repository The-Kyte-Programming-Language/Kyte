# 메모리 관리

Kyte의 메모리 모델은 단순합니다: 기본은 스택, 힙이 필요하면 `Vault`. 힙에 올린 것도 직접 해제할 필요 없습니다 — 컴파일러가 알아서 합니다.

---

## 스택 (기본값)

아무것도 안 해도 모든 변수는 스택에 살아있습니다:

```kyte
int x = 42;          // 스택
string name = "hi";  // 스택 (문자열 포인터 자체)
float f = 3.14;      // 스택
```

스택 메모리는 변수가 범위를 벗어나는 순간 자동으로 사라집니다. 가장 빠르고, GC도 없고, 할당 실패도 없습니다.

---

## 힙 — Vault

다음 두 상황에서는 힙이 필요합니다:

1. **Anchor 재시작을 넘어 데이터를 유지해야 할 때** — Kill이 발생하면 스택은 버려지지만 힙은 살아남습니다.
2. **스택에 담기엔 너무 큰 데이터** — 수 MB짜리 버퍼 등.

그럴 때 `Vault`를 앞에 붙입니다:

```kyte
Vault int counter = 0;
Vault int[] buffer = [1, 2, 3, 4, 5];
Vault string msg = "힙에서 살아있음";
```

내부적으로는 `malloc`을 호출합니다. 할당 실패 시 런타임 오류로 처리됩니다 (NULL 체크 내장).

---

## 자동 메모리 해제

Vault 변수를 `free()`로 직접 해제하지 않아도 됩니다. 컴파일러가 각 변수의 **마지막 사용 지점**을 추적해서 그 바로 다음에 `free()`를 자동 삽입합니다.

```kyte
@main(main) {
    Vault int x = 42;
    Vault int[] arr = [1, 2, 3];

    print(x);           // x의 마지막 사용
    // ← 컴파일러가 여기에 free(x) 삽입

    print(arr[0]);      // arr의 마지막 사용
    // ← 컴파일러가 여기에 free(arr) 삽입

    print("끝");
}
```

이렇게 얻는 것:

- **메모리 누수 없음** — 해제를 깜빡해도 컴파일러가 합니다.
- **해제 후 접근 없음** — 마지막 사용 직후에 해제하니 이미 해제된 메모리를 읽을 수 없습니다.
- **이중 해제 없음** — 각 변수의 해제 지점이 정확히 하나.

### 분기가 있을 때

마지막 사용이 if/else 안에 있으면, 컴파일러는 **두 분기 모두**에서 해제합니다:

```kyte
Vault int val = 100;

if cond {
    print(val);
    // ← 컴파일러: free(val)
} else {
    print(val + 1);
    // ← 컴파일러: free(val)
}
// 어느 분기를 타든 정확히 한 번 해제됩니다
```

### Kill, break, return이 발생할 때

중간에 빠져나가는 경우도 안전합니다. Kyte는 `Kill`, `break`, `return`이 발생하는 시점에 현재 범위에 살아있는 모든 Vault 변수를 즉시 정리합니다:

```kyte
@main(main) {
    Vault int x = 10;
    Vault int y = 20;

    if some_condition {
        Kill "중단";   // x, y 모두 안전하게 해제 후 재시작
    }

    print(x + y);
    // 정상 종료 시 여기서 해제
}
```

## Vault를 쓰는 이유

대부분의 로컬 변수는 스택으로 충분합니다. Vault가 필요한 경우:

### 1. Anchor 재시작 간 상태 유지

```kyte
@main(main) {
    Vault int attempt = 0;   // Kill 후에도 값 유지
    attempt += 1;

    if attempt < 5 {
        Kill "재시도";
    }

    print(f"{attempt}번 만에 완료");
}
```

`int attempt`(스택)라면 매 재시작마다 0으로 리셋됩니다. `Vault int`만이 Kill을 넘어 살아남습니다.

### 2. 대용량 데이터

```kyte
Vault int[] big_buffer = [/* 수천 개의 원소 */];
```

큰 배열을 스택에 올리면 스택 오버플로우 위험이 있습니다. Vault로 힙에 두세요.

---

## 정리

| | 스택 | Vault |
|---|---|---|
| 선언 방법 | `int x = 0;` | `Vault int x = 0;` |
| 해제 | 자동 (범위 종료 시) | 자동 (컴파일러 삽입) |
| Kill 후 생존 | 아니오 (리셋) | 예 |
| 속도 | 가장 빠름 | malloc 오버헤드 |
| 용도 | 거의 모든 것 | 영속 상태, 대용량 |

---

## 권장 패턴

- **스택부터 시작하세요.** `Vault`는 필요할 때만.
- **재시도 로직이 있는 anchor에서는** 카운터/상태 변수만 Vault로, 나머지는 스택으로.
- 이름이 `_`로 시작하는 변수는 미사용 경고가 억제됩니다.
