# 메모리 관리

Kyte는 메모리가 어디에 살지 명시적으로 제어할 수 있게 해줍니다. 기본은 스택 할당. 힙이 필요하면 `Vault`로 요청합니다.

---

## 스택 (기본값)

특별히 말하지 않으면 모든 변수는 스택에 할당됩니다:

```kyte
int x = 42;          // 스택
string name = "hi";  // 스택
float f = 3.14;      // 스택
```

스택 메모리는 변수가 범위를 벗어나면 자동으로 해제됩니다. 빠르고, 결정론적이며, 오버헤드 없음.

---

## 힙 — Vault

변수 앞에 `Vault`를 붙이면 힙에 할당됩니다:

```kyte
Vault int x = 42;
Vault int[] arr = [1, 2, 3, 4, 5];
Vault string msg = "힙에서 온 안녕";
```

내부적으로 Kyte가 `malloc`을 호출하고 `NULL` 여부를 확인합니다. 할당 실패 시 런타임 오류로 처리됩니다.

---

## 자동 메모리 해제

Vault 변수는 **컴파일러가 자동으로 해제합니다** — `free()`를 직접 호출할 필요가 없습니다. 컴파일러는 컴파일 시점에 각 Vault 변수가 마지막으로 읽히는 위치를 추적하는 마지막-사용 생존성 분석(last-use liveness analysis)을 수행하고, 그 직후에 해제 코드를 자동 삽입합니다.

```kyte
@main(main) {
    Vault int x = 42;
    print(x);         // x의 마지막 사용
    // 컴파일러가 여기에 free(x) 자동 삽입
    int y = 100;
    print(y);
}
```

이를 통해:
- **메모리 누수 없음** — 해제를 깜빡해도 괜찮습니다.
- **해제 후 접근(use-after-free) 없음** — 너무 일찍 해제되는 일이 없습니다.
- **이중 해제(double-free) 없음** — 컴파일러가 각 변수의 해제 지점을 정확히 한 번만 추적합니다.

### 분기 처리

Vault 변수의 마지막 사용이 `if/else` 안에 있을 경우, 컴파일러는 **두 분기 모두의 끝**에서 해제합니다. 어느 경로를 타든 정확히 한 번 해제됩니다:

```kyte
Vault int x = 42;
if cond {
    print(x);
    // 컴파일러가 여기서 x 해제
} else {
    print(x);
    // 컴파일러가 여기서도 x 해제
}
```

`else`가 없거나, 마지막 사용이 `loop`, `while`, `for`, `match` 안에 있으면 해당 블록 전체 이후에 해제합니다 — 언제나 안전하고 올바릅니다.

### 조기 종료

`Kill`, `break`, `return`이 발생하면 현재 범위에 남아 있는 모든 Vault 변수를 즉시 정리하는 안전망 패스가 실행됩니다. 조기 종료 시 누수 없음.

---

## Vault를 쓰는 이유

대부분은 스택 할당으로 충분합니다. `Vault`를 쓸 때:

1. **데이터가 범위를 벗어나서도 살아야 할 때** — 예: anchor 재시작을 넘나드는 상태.
2. **데이터가 스택에 담기엔 너무 클 때** — 큰 배열, 버퍼.
3. **포인터 의미가 필요할 때** — 힙 주소를 어딘가에 전달.

### 고전적 사용 사례: anchor 재시작 간 상태 유지

```kyte
@main(main) {
    Vault int attempt = 0;   // 힙 할당, Kill에서 살아남음
    attempt += 1;

    if attempt < 5 {
        Kill "재시도";
    }

    print("완료");
    // 컴파일러가 여기서 attempt 자동 해제
}
```

스택 변수(`int attempt = 0`)는 매 재시작마다 리셋됩니다. `Vault int attempt = 0`은 최초 실행 시 한 번만 초기화됩니다.

---

## 정리

| | 스택 | Vault |
|---|---|---|
| 할당 | 자동 | `Vault` 키워드 |
| 해제 | 자동 | 자동 (컴파일러 삽입) |
| 속도 | 가장 빠름 | malloc 오버헤드 |
| `Kill` 생존 | 아니오 | 예 |
| 용도 | 그 외 모든 것 | 영속성, 대용량 데이터 |
